     1→# AIDetective 🔍
     2→
     3→**An open-source, local-first, multimodal AI-content detection platform.**
     4→
     5→AIDetective analyzes **text, documents, images and audio** with an explainable, weighted ensemble of heuristic detectors. Every result ships with the raw signals, per-signal evidence, a likelihood score, a capped confidence value — and an honest disclaimer.
     6→
     7→> ⚠️ **Read this first: AIDetective is probabilistic.** Its output is an *estimate*, never proof. Detection of AI-generated content can and does produce **false positives and false negatives**. `uncertain` and `inconclusive` are first-class outcomes in this project, and the scoring engine is **capped below 1.0 confidence by design**. Do not use AIDetective as sole evidence to accuse, punish, defame or judge anyone. See [docs/limitations.md](docs/limitations.md).

    52→## What this is / What this is NOT
    53→
    54→| ✅ What this **is** | ❌ What this is **NOT** |
    55→| --- | --- |
    56→| A local-first, self-hosted analysis workbench for AI-content suspicion signals | A court-proof authorship verifier or a forensic tool |
    57→| A deterministic, explainable scoring engine over **heuristic baseline detectors** | A trained ML classifier (no models were trained in this release — the detectors are transparent heuristics) |
    58→| A system that shows its work: every signal, value, weight and evidence quote is inspectable | A black box that returns a single "AI % with certainty" |
    59→| A platform where `uncertain` / `inconclusive` are valid, expected answers | An oracle. Ambiguity is the honest answer for a lot of real-world content |
    60→| A plugin platform (detectors, parsers, LLM providers, report exporters) | A substitute for provenance systems (C2PA, watermarks) — that's on the roadmap |
    61→| An optional LLM layer that **explains** results in plain language | An LLM judge — the LLM can never change the verdict, by prompt-contract *and* by code |
    62→
    63→**Detection is probabilistic.** Treat every classification (`likely_human`, `likely_ai_generated`, `likely_synthetic`) as a starting point for human review, never as the conclusion.

    67→## Features
    68→
    69→- **Four modalities**: text (inline or file), documents (PDF/DOCX), images (PNG/JPG/WEBP), audio (WAV/MP3/FLAC/M4A).
    70→- **15 built-in heuristic detectors** with per-signal `aiScore` (0 = human … 1 = AI, 0.5 = neutral), weight, direction and quoted/statistical **evidence**.
    71→- **Explainable scoring engine**: weighted vote → likelihood score; signal consistency & strength → confidence (hard-capped at 0.92 by default). Full per-signal contribution breakdown is persisted.
    72→- **File analysis pipeline** with magic-byte type detection, filename sanitization, size limits and queued processing (202 + polling).
    73→- **Reports**: structured JSON and self-contained printable HTML (JSON + HTML only in this release; PDF is a planned drop-in via the `ReportExporter` interface).
    74→- **Optional LLM layer** (explanation only): ZAI managed runtime, Ollama, or any OpenAI-compatible API (OpenAI/OpenRouter/custom). Disabled by default.
    75→- **Plugin system**: drop a folder under `plugins/`, and the loader registers your detectors/parsers/LLM providers/exporters at boot — broken plugins are contained and reported, never fatal.
    76→- **REST API** (`/api/v1`) with a unified `{ok, data | error}` envelope, CORS, OpenAPI 3.0.3 description (18 paths), optional API-key auth with per-key rate limits (keys stored sha256-hashed, plaintext shown once).
    77→- **Local-first storage**: SQLite via Prisma; uploaded files stored under server-generated ids inside the `uploads/` directory.
    78→- **Persian + English awareness** in text features (language detection, phrase lists; Persian coverage is explicitly experimental).

    82→## Supported modalities & formats
    83→
    84→Type detection is based on **magic bytes** — the client-supplied filename and MIME type are treated as hints only.
    85→
    86→| Input | Detected as | Pipeline | Analysis level |
    87→| --- | --- | --- | --- |
    88→| Inline text (`POST /api/v1/analyze`) | `text` | Full text feature extraction | **Full** — all 9 text detectors |
    89→| `.txt` / `.md` (markdown lightly stripped) | `text` | Plain-text parser | **Full** — all 9 text detectors |
    90→| `.pdf` | `document` | Text extraction via `unpdf` → text pipeline | **Full (text-level)** — image-only/scanned PDFs get an explicit warning; no OCR |
    91→| `.docx` | `document` | Text extraction via `mammoth` → text pipeline | **Full (text-level)** |
    92→| `.png` / `.jpg` / `.jpeg` | `image` | Metadata (EXIF/PNG chunks, JPEG quantization) + decoded pixel statistics (`sharp`) | **Heuristic baseline** — no trained computer-vision model in this release |
    93→| `.webp` | `image` | Decoded pixel statistics | **Limited** — metadata parsing is limited for WEBP (a warning is attached) |
    94→| `.wav` | `audio` | Container metadata **+ PCM waveform statistics** | **Full (audio-level)** — the only format with waveform analysis |
    95→| `.mp3` / `.flac` / `.m4a` | `audio` | Container/tag metadata only (ID3v2, VORBIS comments, M4A `ilst`) | **Metadata-only** — waveform analysis is WAV-only in this release |
    96→
    97→There is **no speech-to-text / transcript analysis** yet (no ASR, and no Persian ASR). See [Limitations](#limitations) and the [Roadmap](#roadmap).

   159→## Built-in detectors
   160→
   161→All detectors are **transparent heuristics** (no trained models). Each exposes its own honest `limitations` — also visible at `GET /api/v1/detectors`. Weights are relative within a modality and configurable at runtime.
   162→
   163→| Detector id | Modality | What it measures | Weight |
   164→| --- | --- | --- | --- |
   165→| `text.burstiness` | text, document | Variability of sentence lengths (coefficient of variation). Flat rhythm leans AI; bursty rhythm leans human | 0.80 |
   166→| `text.phrases` | text, document | Density of phrases over-represented in LLM output ("delve into", "plays a crucial role", …; English lists full, Persian lists experimental). Matches are quoted as evidence | 0.85 |
   167→| `text.structure` | text, document | Structural "tidiness": uniform paragraph sizes, every sentence capitalized & perfectly terminated, list-like scaffolding | 0.60 |
   168→| `text.vocabulary` | text, document | Lexical richness: root TTR, hapax legomena share, normalized entropy | 0.55 |
   169→| `text.informality` | text, document | Human-tell markers: contractions, informal vocabulary (lol, btw), emoji, letter elongation, ALL-CAPS | 0.55 |
   170→| `text.repetition` | text, document | Repeated exact 4-word sequences (generation artifacts, duplication) | 0.50 |
   171→| `text.punctuation` | text, document | Punctuation habits: !/? usage, em-dash density, ellipses, repeated punctuation, comma regularity | 0.50 |
   172→| `text.connectives` | text, document | Density of formal connectives (however, moreover, furthermore…) | 0.50 |
   173→| `text.lexical_entropy` | text, document | Shannon entropy of the word-frequency distribution, normalized to [0,1] | 0.40 |
   174→| `image.metadata` | image | EXIF/PNG provenance: generative-AI tool tags, camera capture metadata, editor software, C2PA content-credential markers | 0.90 |
   175→| `audio.metadata` | audio | Container/tag metadata (ID3v2, VORBIS, M4A `ilst`, WAV `LIST/INFO`): encoder software and known TTS/speech-synthesis tools | 0.90 |
   176→| `image.dimensions` | image | Dimension profile: canvases typical of diffusion models (multiples of 64) vs camera sensor sizes | 0.45 |
   177→| `audio.waveform` | audio *(WAV only, experimental)* | PCM dynamics: RMS variability across 50 ms windows, silence ratio & pause structure, clipping, DC offset, zero-crossing rate | 0.40 |
   178→| `image.pixel_stats` | image *(experimental)* | First-order pixel statistics: high-frequency energy (Laplacian variance), LSB uniformity, channel balance | 0.30 |
   179→| `image.compression` | image | Compression profile: JPEG quantization-table quality estimate + chroma subsampling, or PNG color/bit-depth profile (mostly descriptive) | 0.25 |
   180→
   181→**Example plugin:** [`plugins/example-text-detector/`](plugins/example-text-detector/) registers `text.example.hedging` (weight 0.35) — a real, deterministic detector that counts hedging/SEO openings ("In this article, we will…", "Let's dive in…") and quotes each occurrence as evidence. It doubles as the reference implementation of the plugin contract.

   185→## Tech stack & design adaptation
   186→
   187→- **Next.js 16 (App Router) + TypeScript** — API route handlers under `src/app/api/v1/**` are the REST layer.
   188→- **Prisma 6 + SQLite** — local-first persistence (schema avoids SQLite-specific features to keep a PostgreSQL migration open).
   189→- **Tailwind CSS 4 + shadcn/ui** — dark analyst workspace UI (sidebar navigation, 11+ views).
   190→- **sharp** (pixel statistics), **exifreader** (image metadata), **unpdf** (PDF text), **mammoth** (DOCX text).
   191→- **Bun** as package manager & runtime; `z-ai-web-dev-sdk` only for the optional managed LLM provider.
   192→
   193→> **Adaptation note (honest):** the original project brief specified a **Python + FastAPI** backend. The implemented backend is **TypeScript on Next.js 16**. What changed: FastAPI routers → Next.js App Router route handlers; Pydantic models → zod + TypeScript interfaces (`src/lib/aidetective/core/types.ts`); a worker queue → an in-process FIFO (`src/lib/aidetective/queue/job-queue.ts`, Redis planned); SQLAlchemy/PostgreSQL → Prisma/SQLite for the local-first default. What did **not** change: the REST contract (paths, unified envelope, OpenAPI 3.0.3 spec, key auth), the detector/analyzer/parser pipeline design, and the scoring engine's deterministic, explainable behavior. The API is framework-agnostic — any HTTP client works.

   197→## Installation
   198→
   199→Requirements: **[Bun](https://bun.sh)** 1.1+ (Node 20+ works for serving, but scripts assume Bun), ~500 MB disk.
   200→
   201→```bash
   202→git clone https://github.com/<org>/aidetective.git
   203→cd aidetective
   204→bun install
   205→cp .env.example .env       # defaults are safe: LLM disabled, local mode
   206→bun run db:push            # creates the SQLite schema
   207→bun run dev                # http://localhost:3000
   208→```
   209→
   210→Open `http://localhost:3000`. In this release, use the REST API (below) or the OpenAPI document at `http://localhost:3000/api/v1/openapi` to explore. On first request the engine bootstraps itself: builtin detectors/parsers/exporters → plugins → queue worker → model-registry seeding.
   211→
   212→Useful scripts: `bun run lint`, `bun run db:generate`, `bun run db:push`, `bun run build`, `bun run start`.

   241→## API usage
   242→
   243→Base URL: `http://localhost:3000`. All responses use the envelope `{"ok": true, "data": …}` or `{"ok": false, "error": {"code", "message", "details?"}}`. CORS is enabled; auth is optional in local mode (see [API keys](#api-keys)).
   244→
   245→**OpenAPI:** `GET /api/v1/openapi` returns a complete **OpenAPI 3.0.3** description (18 paths). Import that URL directly into Swagger UI, Postman, Insomnia or Redoc.
   246→
   247→### Analyze inline text
   248→
   249→```bash
   250→curl -s http://localhost:3000/api/v1/analyze \
   251→  -H "Content-Type: application/json" \
   252→  -d '{
   253→        "content": "In today'"'"'s fast-paced world, it is important to delve into the crucial role of technology. Furthermore, it is worth noting that…",
   254→        "options": { "useLlm": false }
   255→      }'
   256→# → data.classification, data.likelihoodScore, data.confidence, data.signals[], data.detectorRuns[]
   257→```
   258→
   259→### Analyze an uploaded file (multipart → 202 → poll)
   260→
   261→```bash
   262→curl -s -X POST http://localhost:3000/api/v1/analyze/file \
   263→  -F "file=@./sample.pdf" \
   264→  -F 'options={"useLlm":true}'
   265→# → 202 Accepted with a queued analysis; then poll:
   266→curl -s http://localhost:3000/api/v1/analyses/<id>      # until status: completed | failed
   267→```
   268→
   269→### List / search analyses
   270→
   271→```bash
   272→curl -s "http://localhost:3000/api/v1/analyses?modality=image&status=completed&sort=createdAt&order=desc&page=1&pageSize=20"
   273→```
   274→
   275→Query params: `query, modality, classification, status, from, to, sort (createdAt|likelihoodScore|confidence|processingTime), order, page, pageSize (≤100)`.
   276→
   277→### Get a report (JSON or HTML)
   278→
   279→```bash
   280→curl -s "http://localhost:3000/api/v1/reports/<id>?format=json" | jq
   281→curl -s "http://localhost:3000/api/v1/reports/<id>?format=html" -o report.html   # self-contained, printable
   282→```
   283→
   284→Both embed software/version info and a prominent disclaimer. Reports are generated only for `completed` analyses (409 otherwise). JSON + HTML only in this release (PDF is on the roadmap as a drop-in exporter).
   285→
   286→### API keys
   287→
   288→Auth is **optional local-mode** by default (`AIDETECTIVE_REQUIRE_API_KEY=false`): requests without a key are accepted from local clients; if a key is provided it is validated. Enable enforcement for shared/remote deployments.
   289→
   290→```bash
   291→# Create a key (plaintext shown ONCE — only its sha256 is stored)
   292→curl -s -X POST http://localhost:3000/api/v1/api-keys \
   293→  -H "Content-Type: application/json" \
   294→  -d '{"name": "my-client", "rateLimit": 60}'
   295→# → {"ok":true,"data":{"key":"adk_5f3c…","prefix":"adk_5f3c…","…"}}
   296→
   297→# Use it (Bearer or X-API-Key)
   298→curl -s http://localhost:3000/api/v1/analyses \
   299→  -H "Authorization: Bearer adk_5f3c…"
   300→
   301→# Revoke later
   302→curl -s -X DELETE http://localhost:3000/api/v1/api-keys/<keyId>
   303→```

   326→## LLM setup
   327→
   328→The LLM layer is **optional and explanation-only**. The verdict, score and confidence come exclusively from the deterministic scoring engine. The interpretation receives only the structured result (classification, score, confidence, up to 20 compacted signals, key evidence quotes) and its system prompt forbids changing, re-computing or confirming the verdict. If the LLM call fails, the analysis completes normally and a warning is attached. Configure via environment variables **and/or** runtime settings (`GET/PUT /api/v1/settings`; the dashboard LLM/Settings pages provide the same controls). A request only triggers an interpretation when LLM support is enabled **and** `options.useLlm: true` is sent. `POST /api/v1/llm/test` verifies connectivity.
   329→
   330→| Provider | `AIDETECTIVE_LLM_PROVIDER` | Required env | Notes |
   331→| --- | --- | --- | --- |
   332→| **ZAI managed runtime** | `zai` | none | Works without user-side keys (used in managed sandboxes); model `glm-4.5-flash` |
   333→| **Ollama (local)** | `ollama` | `AIDETECTIVE_LLM_BASE_URL` (e.g. `http://localhost:11434`) | Default model `llama3.1` (`AIDETECTIVE_LLM_MODEL` to override); fully offline |
   334→| **OpenAI-compatible** | `openai_compatible` | `AIDETECTIVE_LLM_BASE_URL` (e.g. `https://api.openai.com/v1`, `https://openrouter.ai/api/v1`) | Optional `AIDETECTIVE_LLM_API_KEY` (Bearer); default model `gpt-4o-mini` |
   335→
   336→```bash
   337→# Example: local Ollama
   338→AIDETECTIVE_LLM_ENABLED=true
   339→AIDETECTIVE_LLM_PROVIDER=ollama
   340→AIDETECTIVE_LLM_BASE_URL=http://localhost:11434
   341→AIDETECTIVE_LLM_MODEL=llama3.1
   342→
   343→# Example: OpenRouter
   344→AIDETECTIVE_LLM_ENABLED=true
   345→AIDETECTIVE_LLM_PROVIDER=openai_compatible
   346→AIDETECTIVE_LLM_BASE_URL=https://openrouter.ai/api/v1
   347→AIDETECTIVE_LLM_MODEL=meta-llama/llama-3.1-8b-instruct
   348→AIDETECTIVE_LLM_API_KEY=sk-or-...
   349→
   350→# Verify:
   351→curl -s -X POST http://localhost:3000/api/v1/llm/test
   352→```
   353→
   354→The interpretation is stored on the analysis (`llmInterpretation`, `llmProvider`, `llmModel`) and appears in reports — clearly separated from the engine's signals.

   358→## Plugin development
   359→
   360→Full guide with runnable code: **[docs/plugins.md](docs/plugins.md)**. Contract summary:
   361→
   362→```
   363→plugins/<my-plugin>/
   364→├── plugin.json   # manifest: { id, name, version, type, modality?, entry, description? }
   365→└── index.js      # ESM, must export: register(api)
   366→```
   367→
   368→`type` ∈ `detector | parser | llm_provider | exporter`. The loader scans `plugins/` at boot (fixed root, no traversal), validates manifests, dynamic-imports the entry at runtime (never bundled, never `eval`ed) and calls `register(api)` with:
   369→
   370→```js
   371→api.registerDetector(detector)      // Detector object (see below)
   372→api.registerParser(parser)          // FileParser — new input formats
   373→api.registerLLMProvider(provider)   // registered for visibility; the active provider is resolved via settings (no silent hijack)
   374→api.registerExporter(exporter)      // ReportExporter — e.g. a future PDF exporter
   375→```
   376→
   377→Every registration is validated; a throwing plugin is recorded with status `error` (visible at `GET /api/v1/plugins` and in the DB) and **cannot crash the app**. Restart to reload plugins. Start from [`plugins/example-text-detector/`](plugins/example-text-detector/).

   381→## Detector development
   382→
   383→A detector is a plain object implementing the `Detector` interface from [`src/lib/aidetective/core/types.ts`](src/lib/aidetective/core/types.ts):
   384→
   385→```ts
   386→interface Detector {
   387→  id: string;                    // e.g. "text.my-detector" (namespaced by modality)
   388→  name: string;
   389→  version: string;               // bump when behavior changes — stored per run
   390→  description: string;
   391→  modalities: Modality[];        // "text" | "image" | "audio" | "document"
   392→  defaultWeight: number;         // 0..1, relative importance inside the modality
   393→  limitations: string[];         // honest, user-visible — mandatory
   394→  analyze(ctx: DetectorContext): Promise<{
   395→    status: "ok" | "skipped" | "error";
   396→    signals: Signal[];
   397→    summary?: string;
   398→    error?: string;
   399→  }>;
   400→}
   401→
   402→interface Signal {
   403→  id: string;                    // e.g. `${detectorId}.low_variance`
   404→  detectorId: string;
   405→  name: string;
   406→  value?: number | string | boolean | null;
   407→  unit?: string;
   408→  aiScore: number | null;        // 0 = strongly human, 0.5 = neutral, 1 = strongly AI; null = not quantifiable
   409→  weight: number;
   410→  evidence: EvidenceItem[];      // quotes / statistics / metadata / observations
   411→  notes?: string;
   412→}
   413→```
   414→
   415→`ctx` provides `input` (text or buffer + metadata), `modality`, pre-extracted `features` and `options`. Rules of the house:
   416→
   417→- **Always fill `limitations`** — detectors that hide their weaknesses are rejected in review.
   418→- Return `status: "skipped"` when the input can't support the measurement (e.g. too few sentences); return `aiScore: null` for descriptive-but-unquantifiable findings.
   419→- A thrown error never aborts the analysis — it is recorded per detector and surfaced as a warning.
   420→- The scoring engine clamps weights to [0, 1] and lets users override weights per detector id via settings.

   482→## Testing
   483→
   484→The project ships with a real, automated test suite (`bun test`, **186 tests / 869 assertions** across 12 files) — no mocks of engine logic, no faked results:
   485→
   486→- **Unit tests** (`tests/unit/`): scoring engine math (weighted votes, polarity, consistency, confidence cap, uncertain/inconclusive rules, weight overrides); text feature statistics; **all 15 detectors with determinism guarantees** (identical input → identical output, JSON-deep) and honest-signal direction checks; image pipeline (real crafted PNG/JPEG buffers: IHDR/tEXt parsing, DQT quality inversion, JFIF chroma-subsampling classification, sharp pixel statistics); audio pipeline (real crafted WAV/MP3/FLAC/M4A buffers: PCM decoding with known RMS/peak values, ID3v2/TTS-hint parsing, FLAC STREAMINFO); file security (magic-byte detection vs lying extensions, filename sanitization, size limits, storage-path containment); parsers (TXT/MD/PDF/DOCX with real crafted files); job queue (FIFO, concurrency, crash containment); registry/plugin loading (the bundled example plugin is loaded from disk); LLM gating (explanation-only, provider-agnostic); report exporters (JSON structure + HTML escaping).
   487→- **Integration tests** (`tests/integration/`): run against the **live server** — every `/api/v1/` endpoint, the full `upload → queue → analysis → database → report` flow for PNG/TXT/DOCX/PDF/WAV/MP3, structured error envelopes (400/404/409/413/415/429), CORS preflight, history search/filter/sort/pagination, datasets & models CRUD, API-key lifecycle (create → use → revoke → 401) and per-key rate limiting, and end-to-end **determinism** (the same text analyzed twice returns an identical verdict, score and signal set).
   488→
   489→Run them:
   490→
   491→```bash
   492→bun test          # everything (integration tests skip with a notice if the server is not running)
   493→bun test tests/unit/         # engine-only, no server needed
   494→bun run lint && bun run build  # quality gates
   495→```
   496→
   497→The integration suite writes real rows (analyses/datasets/keys) into your database and cleans up after itself; keys it creates are revoked and visible in the dashboard as audit history.

   501→## Limitations
   502→
   503→Full, maintained list: **[docs/limitations.md](docs/limitations.md)**. Summary (all of these are also surfaced as warnings by the API/UI):
   504→
   505→- **No trained ML models.** All 15 detectors are heuristic baselines. Accuracy is unknown-by-benchmark; do not assume published AUC figures apply.
   506→- **Detection is probabilistic and dual-sided**: false positives (human work flagged as AI) and false negatives (AI work flagged as human) both occur. Short texts (< ~120 words) are explicitly flagged as unreliable.
   507→- **Audio**: waveform analysis is **WAV-only**; MP3/FLAC/M4A are metadata-only; **no ASR/transcript analysis**, no Persian ASR.
   508→- **Images**: no trained computer-vision model; WEBP metadata parsing is limited; no GPU detection.
   509→- **Datasets**: text-only import/export (no image/audio datasets yet); no evaluation harness yet.
   510→- **Reports**: JSON and self-contained HTML only (no PDF exporter yet).
   511→- **Queue**: in-memory FIFO — no persistence across restarts, no distributed workers.
   512→- **LLM layer** is optional and explanation-only; it never decides verdicts (and cannot).
   513→- **Auth** is optional local-mode by default — enable `AIDETECTIVE_REQUIRE_API_KEY` for any shared deployment.
   514→- **Web dashboard** is under active development; this release is API-first.
   515→
   516→> ⚠️ **Responsible use:** AIDetective provides a probabilistic analysis — its output is **not proof** of authorship or origin. Do not use it for legal accusations, disciplinary action, defamation, or harassment. Humans are routinely misclassified; treat results as one input among several, and always involve human review.

   540→## Environment variables
   541→
   542→All variables are read at boot by [`src/lib/aidetective/core/config.ts`](src/lib/aidetective/core/config.ts). See [`.env.example`](.env.example) for a commented template.
   543→
   544→| Variable | Default | Purpose |
   545→| --- | --- | --- |
   546→| `DATABASE_URL` | `file:./db/custom.db` | SQLite connection (local-first). Relative paths resolve against `prisma/schema.prisma`; use an absolute path in Docker (`file:/app/db/custom.db`) |
   547→| `AIDETECTIVE_REQUIRE_API_KEY` | `false` | Require API keys on `/api/v1` (local dashboard mode works without) |
   548→| `AIDETECTIVE_MAX_UPLOAD_MB` | `25` | Upload size limit in MB (60 MB HTTP hard cap) |
   549→| `AIDETECTIVE_MAX_TEXT_CHARS` | `200000` | Inline text length limit |
   550→| `AIDETECTIVE_LLM_ENABLED` | `false` | Enable the optional (explanation-only) LLM layer |
   551→| `AIDETECTIVE_LLM_PROVIDER` | `zai` | `zai` \| `ollama` \| `openai_compatible` |
   552→| `AIDETECTIVE_LLM_BASE_URL` | — | Required for `ollama` / `openai_compatible` |
   553→| `AIDETECTIVE_LLM_MODEL` | provider default | e.g. `llama3.1`, `gpt-4o-mini` |
   554→| `AIDETECTIVE_LLM_API_KEY` | — | Bearer key for `openai_compatible` |
   555→| `AIDETECTIVE_LLM_TEMPERATURE` | `0.2` | Generation temperature |
   556→| `AIDETECTIVE_LLM_TIMEOUT_MS` | `25000` | LLM call timeout |
   557→| `AIDETECTIVE_QUEUE_CONCURRENCY` | `1` | In-memory FIFO worker count |
   558→| `AIDETECTIVE_UPLOADS_DIR` | `uploads` | Upload storage directory (server-generated filenames) |
   559→| `LOG_LEVEL` | `info` | `debug` \| `info` \| `warn` \| `error` (structured, redacted) |
   560→| `AIDETECTIVE_DEBUG_CONTENT` | `false` | Log raw user content — debug only, never in production |
   561→| `AIDETECTIVE_SCORING_AI_THRESHOLD` | `0.62` | Score ≥ threshold → `likely_ai_generated` / `likely_synthetic` |
   562→| `AIDETECTIVE_SCORING_HUMAN_THRESHOLD` | `0.42` | Score ≤ threshold → `likely_human` |
   563→| `AIDETECTIVE_SCORING_MIN_SIGNALS` | `2` | Fewer usable signals → `uncertain` |
   564→| `AIDETECTIVE_SCORING_MAX_CONFIDENCE` | `0.92` | Hard confidence cap (always < 1.0 by design) |

   568→## Contributing
   569→
   570→Contributions are welcome — especially **new detectors** (with honest `limitations`), parsers, exporters and evaluation datasets.
   571→
   572→1. Read [docs/architecture.md](docs/architecture.md) and [docs/plugins.md](docs/plugins.md).
   573→2. Small PRs beat big ones; keep the detector contract (`core/types.ts`) stable.
   574→3. Every detector must document its limitations and failure modes — no exceptions.
   575→4. Don't invent certainty: keep `uncertain`/`inconclusive` behavior intact, and keep the confidence cap.
   576→5. Open an issue before large refactors. Run `bun run lint` before submitting.
